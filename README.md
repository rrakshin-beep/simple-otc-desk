# OTC Desk 2.0

Рабочая демонстрационная версия OTC-деска на FastAPI и SQLAlchemy, подготовленная для дальнейшего развития криптовалютной биржи в Кыргызской Республике.

## Основные возможности

- кабинеты клиента, OTC-дилера и комплаенса;
- создание RFQ от количества криптовалюты или суммы фиата;
- котирование, срок действия, отклонение и идемпотентное принятие котировки;
- управляемый жизненный цикл сделки и история каждого статуса;
- банковская и сетевая комиссии в соответствующих валютах;
- банковский референс, сеть, TX hash и AML-риск;
- архивирование без физического удаления;
- сводный отчет и экспорт CSV/XLSX;
- карточки юридических и физических лиц;
- профиль подотчетного лица;
- регуляторная карточка сделки по Форме 1;
- структурно-логическая проверка обязательных полей;
- генерация XML в кодировке Windows-1251;
- форматы дат, сумм, листов и участников, совместимые с описанием АРМ ФУС.

## Разделы

- `/client` — клиентский кабинет;
- `/dealer` — кабинет OTC-дилера;
- `/compliance` — кабинет комплаенса;
- `/parties` — клиенты и контрагенты;
- `/reports/trades` — сводный отчет;
- `/regulatory` — регуляторная отчетность;
- `/settings/reporting` — данные подотчетного лица;
- `/docs` — OpenAPI.

## Запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```

Открыть: `http://127.0.0.1:8000/client`.

## Railway

Start Command:

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Dockerfile уже содержит эту команду. Для SQLite рекомендуется подключить Railway Volume. Для PostgreSQL задайте переменную `DATABASE_URL` и добавьте PostgreSQL-драйвер в зависимости.

## Ограничения

Это расширенный прототип, а не готовая промышленная финансовая система. Интерфейсы ролей пока не защищены полноценной авторизацией. Справочники кодов СФР не включены: коды операций, участников, документов и признаков должны быть загружены из актуальной НСИ. Перед промышленным использованием нужны RBAC, 2FA, Alembic, PostgreSQL, управление секретами, резервное копирование, интеграции KYC/AML/Wallet и независимое тестирование безопасности.

## Форма 1

В карточке каждой сделки доступна кнопка **«Форма 1»**.

Маршруты:

- `GET /trades/{trade_id}/form1` — открыть форму;
- `POST /trades/{trade_id}/form1` — сохранить данные;
- `GET /trades/{trade_id}/form1/validate` — выполнить структурно-логическую проверку;
- `GET /trades/{trade_id}/form1.xml` — скачать XML в кодировке Windows-1251.

Старые маршруты `/regulatory` сохранены для обратной совместимости.
